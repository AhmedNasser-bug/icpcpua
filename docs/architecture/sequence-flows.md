```mermaid
    Student->>UI: Open /events/:id/check-in?token=<rawToken>
    UI->>Adapter: api("/events/:id/check-in", { method: "POST", body: { token } })
    Adapter->>Adapter: tokenHash = sha256(rawToken)
    Adapter->>FS: runTransaction(get event, get registration {eventId}_{uid}, get user {uid})
    FS->>FS: Rules verify auth.uid, time window, tokenHash, checkedInAt == null
    Adapter->>FS: update registration { checkedInAt, pointsAwarded: event.attendancePoints }
    Adapter->>FS: update users/{uid} { attendancePoints += pts, verifiedAttendanceCount += 1 }
    FS-->>Adapter: Commit OK
    Adapter-->>UI: { registration, pointsAwarded }
```

## Analysis Notes

- **Critical paths:**
  - Flow 1 ensures seamless session persistence via `onAuthStateChanged` while returning a shape compatible with `localStorage.getItem('token')` in `App.jsx`.
  - Flow 2 guarantees that a student cannot award themselves arbitrary points: `firestore.rules` validates that `request.resource.data.pointsAwarded == get(/databases/$(database)/documents/events/$(eventId)).data.attendancePoints`.
- **Risk areas:**
  - Popup blockers on mobile browsers during OAuth: fallback to `signInWithRedirect` if `signInWithPopup` throws `auth/popup-blocked`.
- **Stale/dead code suspects:**
  - Legacy `POST /api/auth/login` and `POST /api/auth/register` password endpoints are retained in the adapter only as compatibility shims for tests or redirected to OAuth.
